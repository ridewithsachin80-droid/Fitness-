## What was done

**1. Design tokens** (`tailwind.config.js`). Colours: `charcoal, surface, input, gold,
gold-light, gold-deep, gold-dark, bright, soft, mid, mute, lo, faint, dim, ghost, ok, warn,
danger, info, hair, hair-med, hair-hi`. Type: `tiny 9, eyebrow 10, caption 11, micro 11.5,
note 12, body-sm 13, body 15, num-sm 20, num 26, num-lg 30`. (`base` was avoided on purpose:
`text-base` is Tailwind's 16px size.)

**2. Class sweep.** 2,769 class tokens in 39 files rewritten from Tailwind's light palette
(`text-stone-400`, `bg-emerald-600`), brand hexes (`text-[#7E8596]`), rgba tints and pixel
sizes to the tokens. Done by `server/scripts/lib/sweep-classes.js` against
`class-map.json` so the whole migration is a reviewable table. `--check` is idempotent.

**3. Proof of no visual change.** The original and the new client were both built and the
CSS declaration of every one of the 148 mappings compared: **130 render the identical
colour.** The rest are the intentional fixes below. Every token class the JSX uses is
confirmed generated by Tailwind.

**4. Intentional visual fixes** — hover/alpha variants the old override layer could not
reach, so they rendered Tailwind's LIGHT theme on the dark app:
- Coach member page: a row band at `bg-stone-50/60` (near-white at 60%) → faint white 3%
- Admin: dashed add button `bg-white/60 hover:bg-white/90` → 4% / 8%
- Two food rows with a light-grey `border-stone-300` → hairline
- `hover:text-stone-700` (text near-invisible under the thumb) → white
- `hover:border-stone-400`, `hover:border-stone-200` → hairlines
- Prescribed-meal rows `bg-emerald-50/50`, `bg-amber-50/50` → gold / amber tints
- `hover:text-red-600`, `hover:bg-red-50` → the same red-400 the rest of the app uses
- `border-blue-100` → blue tint · `text-emerald-100` (a lavender rebrand leftover) → white
- `border-stone-800` appeared only inside a comment

**5. lib/day.** `calcFoodMacros, calcMicros, addSupplementMicros, addActivityMicros,
countMicrosMet, calcBMR, foodKcal, dayBalance, sleepMinutes, formatSleep, sleepTone,
deriveActivityTicks, pendingLabels` moved out of `DailyLog.jsx` into pure modules. Two
drift bugs fixed on the way: `calcBMR` existed twice (DailyLog and Profile), and Profile's
calorie sum ignored the static-table fallback that Today used, so the two screens could
show different totals for the same day. One definition each now. `test-day-lib.js` (60
assertions) pins every function with golden values computed from the ORIGINAL inline code.

**6. Primitive kit** (`client/src/components/primitives/`): `Sheet` (drag-to-dismiss
bottom sheet, keyboard-safe via visualViewport, scroll lock, focus return, Escape),
`Segmented` (sliding pill tabs, arrow keys), `HeroNumber` (Fraunces numeral with count-up
on change), `Eyebrow`, `Pressable` (44px hit area, haptic, press scale, 5 variants),
`Skeleton/SkeletonText/SkeletonCard`, `EmptyState`, `Stagger`, `Icon` (45 icons in the orb's
line style). All respect reduce-motion. Nothing on a live screen uses them yet — that is
Sprint 3. They are covered by 26 jsdom assertions and visible on `/dev/kit` when running
`npm run dev` in `client/`.

Note: the folder is `primitives/`, not `ui/` — `ui/` would collide with the existing
`UI.jsx` on macOS/Windows, where the filesystem ignores case.

**7. Tests.** Gate 1,710 → 1,802. Every new assertion was mutation-checked (the function
was broken, the assertion went red, the function was restored).
